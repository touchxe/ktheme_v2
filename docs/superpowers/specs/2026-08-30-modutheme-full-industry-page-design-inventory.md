# 모두테마 전체 업종 페이지·섹션·템플릿 디자인 인벤토리

Date: 2026-08-30  
Status: reviewed specification

## Who

- 모두테마의 업종별 데모와 판매 패키지를 기획하는 운영자
- 외부 디자인 도구에서 페이지 시안을 제작하는 디자이너/에이전트
- 시안을 Elementor, WordPress 템플릿, ModuTheme 위젯으로 구현하는 개발자
- 최종 홈페이지에서 콘텐츠와 예약·상담·상품을 운영하는 현장 담당자

## What

15개 업종, 100개 운영 주체 항목, 61개 프리셋의 기본 페이지를 통합하고, 현재 ModuTheme v0.3.62의 51개 템플릿·18개 파트·4개 패턴과 비교해 다음을 정의한다.

- 업종별 페이지 목적, 포함 내용, 권장 섹션, 현재 자산 대비 상태
- 재사용 가능한 현재 디자인
- 변형 설계가 필요한 페이지와 섹션
- 신규 페이지 원형과 신규 공통 섹션
- 외부 도구 제작 순서와 완료 기준

## Why

업종별 사이트를 각각 처음부터 디자인하면 같은 프로필, 일정, 자료, 폼, 위치 UI가 반복되고, 반대로 제품 비교·예약 상태·사례 상세·커머스처럼 현재 교회 테마에 없는 화면이 누락된다. 페이지 목적과 공통 원형을 먼저 고정해 중복 제작을 줄이고 판매 패키지의 완성도를 일정하게 유지한다.

## Success

1. 모든 업종과 프리셋이 안정적인 ID로 식별된다.
2. 각 업종에 필요한 목록·상세·폼·시스템 페이지가 빠짐없이 정의된다.
3. 각 페이지에 목적, 핵심 내용, 권장 섹션, 현재 테마 비교 결과가 있다.
4. 외부 도구가 JSON 카탈로그를 읽어 동일한 명칭과 ID로 화면을 생성할 수 있다.
5. 신규 디자인이 페이지 원형과 범용 섹션으로 분리되어 재사용 우선순위를 판단할 수 있다.
6. 데스크톱/모바일과 빈 상태·오류·마감·완료 상태가 제작 범위에 포함된다.

## Constraints

- 현재 사용 중인 테마 경로는 `wp-content/themes/modu-theme`로 감사한다.
- 사용자가 진행 중인 테마 디렉터리 명칭 변경은 수정하거나 되돌리지 않는다.
- 디자인은 `docs/DESIGN.md`와 업종별 IA/slug 규칙을 따른다.
- 프리셋 간 차이는 색상만이 아니라 1차 전환, 메뉴, 콘텐츠 모델 중 하나 이상 달라야 한다.
- 테마에 페이지 파일이 있어도 실제 업종 데이터와 상태를 처리하지 못하면 `보유`로 판정하지 않는다.
- 폼·상품·예약·게시물 데이터는 테마가 아니라 플러그인 또는 외부 시스템이 소유한다.

## Out of scope

- 이번 작업에서는 외부 디자인 도구 호출, Elementor 페이지 생성, 신규 위젯 구현을 하지 않는다.
- 라이브 서버와 원본 개발 저장소의 manifest를 변경하지 않는다.
- 제안 상태인 8개 구형 업종의 프리셋 ID를 upstream 확정값으로 간주하지 않는다.
- 실제 의료·법률·후원·환불 정책을 대신 작성하지 않는다.

## Decision

외부 디자인은 업종별 61개 프리셋을 한 번에 각각 제작하지 않는다. 먼저 예약형, 상담형, 견적형, 구매형, 미디어/공동체형, 기관/포털형의 6개 홈 프레임과 공통 페이지 원형을 만든 뒤 프리셋 토큰과 콘텐츠 모델로 확장한다.
